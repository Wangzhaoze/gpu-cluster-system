# 门户功能更新与手动应用说明（2026-10-08）

本次交付只修改仓库代码、测试和文档，没有执行部署、数据库迁移或服务重启。运行中的门户继续使用原镜像，手动执行下面的脚本后才启用新功能。用户编辑的 `TODO.md` 和现有 `.env` 保留。

## 功能变化

| 项目 | 更新后的行为 |
| --- | --- |
| GPU 总览 | admin/member 统一：空闲绿色、调试蓝色、训练橙色、外部占用灰色；卡片与状态标识配色一致，显示“用户：xxx”，移除风扇和显存控制器利用率 |
| 默认资源 | 新训练、调试默认 4 个 CPU 线程和 4 GB 内存；显示和编辑使用 GB，API 继续使用 MiB（4 GB 对应 4096 MiB） |
| GPU 选择 | 训练和调试至少一张 GPU，可自动或手动选择多张，受成员 GPU 配额限制；占用、外部占用或监测不可用的显卡置灰，不提供仅 CPU 选项 |
| Kill | 总览训练队列和训练列表支持 Kill；成员只能操作自己的任务，其他人的按钮置灰；管理员可以操作任意训练，由调度器停止并保存日志 |
| TXT 日志 | 每条训练的“保存 TXT 日志”与“打开日志”并排，弹出的日志窗口中不再放下载按钮；其他成员的私有日志不可读取 |
| 延长训练 | 只有管理员可以延长，沿用原容器和启动时间，更新到期时间，总时长仍受已有七天训练上限限制 |
| 调试限制 | 新建或编辑最多 8 小时，可以按账号设置更低上限；同一成员只能有一个未结束会话，排队、等待审批、启动、运行和停止处理中均计入；一个会话仍可使用多张 GPU |
| 公告 | 管理员新增、编辑和保存草稿，预览并确认发布；草稿不推送，已发布内容不可修改，需要变更时新建公告 |
| 公告接收 | 成员在线时每三秒查询未读公告，登录后也会收到；按发布顺序逐条弹出小窗口，底部关闭按钮成功记录为本人已读后才关闭；失败可重试，多次登录保留已读状态 |
| 历史记录 | 已结束训练、调试的记录和任务日志仅保留最近七天；调度器启动时和每小时清理一次，列表立即过滤过期记录 |

七天从结束时间计算，旧记录缺少结束时间时使用创建时间。运行、排队和等待审批的记录不清理。清理仅移除过期任务记录、其日志及仍残留的已停止平台任务容器；成员代码、workspace、持久化 Python 环境、训练输出、数据集和备份保留。容器仍在运行或清理失败时保留记录以便重试。

本次不会把已经运行的任务强制改成 4 CPU/4 GB，也不会缩短已启动调试的原到期时间。更新后新建和编辑遵守新限制，超过 8 小时的旧排队申请不能按原时长启动或获批，管理员需要先调整；旧的仅 CPU 训练不能直接重试，需要新建并选择 GPU。已有学生工作区和任务容器不被更新脚本重建。

## 手动应用

使用宿主机 `local` 用户运行：

```bash
cd /home/local/gpu-cluster-system
./apply-latest.sh --remote
```

脚本默认应用当前目录的代码，包括本地未提交修改，不切换分支、不自动拉取远端代码。只要旧公网隧道容器还在，就自动保留它；`--remote` 还会在隧道不存在或停止时启动公网访问，停止后重新启动 Quick Tunnel 可能取得新链接。最终打印当前链接。

| 参数 | 用途 |
| --- | --- |
| 无参数 | 应用本地代码并启动所需服务；已有公网隧道自动保留 |
| `--remote` | 同时保证公网隧道启动 |
| `--restart` | 即使应用镜像未变化，也重建 backend/frontend 服务容器；学生容器保留 |
| `--no-build` | 使用已有应用镜像启动/恢复，不构建，因此不会包含尚未构建的新代码 |
| `--pull` | 先对当前分支执行 fast-forward pull，需要已跟踪文件没有本地改动 |

现有 `.env`、已安装 Docker/Compose 和配置的基础镜像需要可用。宿主机编辑器启用时，脚本要求由 `.env` 中配置的宿主机用户执行，以管理其用户级服务。

## 重复执行与失败恢复

脚本使用进程锁防止同时更新，先检查配置和可回退的应用镜像，再构建。通过构建输入指纹，只有变化的 backend/frontend 才重新构建；不重做 CUDA/PyTorch 学生基础镜像。共享构建缓存保留供后续复用，不执行全局 prune，不删除 Docker 卷或学生容器。

原有 PostgreSQL、Traefik、GPU 监控、宿主机代理和公网隧道保留其容器与镜像，停止时原地启动，缺失时用已有镜像创建。应用更新前暂停调度器，更新后验证经 Traefik 的页面和 API、调度器新的心跳，以及公网隧道连接注册。

成功后，只清理脚本明确记录的已替换应用镜像，且必须无标签、无任何容器引用（包括停止的容器）、无环境模板引用。若本次构建临时拉取了 Node builder，清理其临时标签；失败留下的候选列表会在下一次成功运行时继续处理。不进行无关镜像、备份和数据删除。

构建失败时恢复应用标签并保持原服务运行；切换之后失败时尝试恢复原应用镜像与先前运行的调度器，保留已完成的增量数据库迁移。新增公告表与旧代码兼容，回退启动会绕过旧镜像无法识别新迁移版本的问题。第一次启动没有旧应用镜像时不能回退到不存在的服务，脚本报错退出并保留数据，修正错误后可重试。健康检查失败不会输出成功。
